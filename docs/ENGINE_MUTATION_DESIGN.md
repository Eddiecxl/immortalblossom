# 可变世界规则与因果结算设计

目标：玩家能用普通玩法或言出法随改变世界实例，而后续物品、人物、任务与叙事必须读取**当前实例**重新计算。模板只提供初始值，不是存档中的永久真理。自然语言模型可以把玩家指令翻译成候选意图，但不能直接改写存档；Engine 执行、校验、记录和回滚。

一个修改应依次经过：玩家输入 → 结构化意图（目标、范围、操作、来源）→ 读取当前世界规则与实体 → 在副本中检查前置条件、边界和所有权 → 原子应用 → 重算依赖关系 → 记录因果和实际效果 → 保存。任何失败都不得只提交一部分。重复事务 ID 必须幂等。

规则范围：没有指明全局时，个人指令只影响目标；明确写“整个世界／天下”才改变世界规则。世界境界表和当前全局上限存在 `astraWorld.rules.cultivation`；角色的 `cultivation.maxRealmId` 可覆盖个人上限。旧存档若没有规则字段，读取默认规则而不覆盖已有角色状态。普通境界效果读取当前允许的上限，达到上限后产生可见的无效果结果，不能再提高境界或附带加气血。若玩家明确修改规则本身，先修改规则再让后续效果读取新值。

依赖关系按实体 ID 和状态处理：人物死亡会影响其持有物与关联任务；地点毁坏会影响道路、居民和目标任务；势力变化影响成员与领地；物品使用只根据实时持有者、数量与效果条件结算。事件日志保存“请求—实际变更—无效果原因”，方便 SQLite 和叙事查询，不以 AI 的文字充当状态变更。

本轮实现第一批可验证的通用基础：可持久化的境界规则与个人/全局上限、根据当前规则计算境界效果和上限无效果、指定范围的言灵境界改写、真实结果日志与 UI 境界名称。`astra-variables.js` 把人物财富、势力实力/财富/稳定、地点人口/危险及主角气血/财富/安全等数值注册为可结算字段；边界写在存档 `rules.variables`，普通物品和部分世界回合读取同一规则。明确数值言灵只改变已存在的实体；结算时记录真实增量，势力归零还会解除成员与领地关联。

该层**不等于**任意自然语言都已可执行。新物品效果仍需 Engine 已知的结构化效果；关系、任务目标、人物身份和新规则语义尚无通用表达式与依赖图。不能把 AI 编造的故事视为已执行改动。后续应扩展类型化意图、条件/依赖图、安全的 AI 意图翻译，并用多 seed、存档往返及复杂交叉变更测试验收。
