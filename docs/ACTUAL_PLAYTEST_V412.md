# v4.1.2 实际窗口复玩与发布记录

在用户指定的已安装目录，使用真实 RuntimeHost、原生 WebView2、Qwen3 14B Q4_K_M 和 SQLite 跑游戏。测试专用原生宿主仅将 WebView 配置及 SaveRoot 重定向到临时测试目录；游戏、模型和 API 路由均使用实际安装内容。不读取玩家命簿，不调用 Groq 或其他云端生成。

两种不同 seed（临溪镇、白鹿书院）分别跑原版与修改后的开局、困惑、身份、帮忙、下一步、拒绝改道、再次确认位置。随后实测出发、途中询问与长途抵达。真实游玩超过40回合；这是短流程诊断，并非100小时通关或所有 seed 验收。复现工具：Source/tests/Invoke-NativeNarrativePlaytest.ps1、native-narrative-driver.js；使用新的 OutputRoot，可加 TravelOnly 单独验证旅行。原始请求、回复、状态与 SQLite 检查点边界保存在本目录 playtests 下。

## 查明并修正的原因

- 原开局是三段固定模板，并非 AI 写出的开场。现在明确穿越身份，从真实在场人物、目标、有效任务和道路提供第一步；无人物时不凭空造一个人。普通“？”作为困惑处理。支持任意 seed、存档中已改名或改目标的角色。
- 原本地提示强制一个人物对白且不给旁白，过去回复全文又作为近期范文反复送入。现在允许短反应与明确回应，历史仅保留交谈边界，最后强调本轮问题；原始事实和完整行记仍在本地保存。普通模式不发送仅适用于言灵的整段字段说明；言灵仍获得完整提案协议。
- 模型失败或候选无效时曾静默使用泛泛的 Engine 兜底。现在有限回应解释地点、人物、真实目标与可问线索，turn.diagnostics 记录降级，系统与 UI 都告知玩家。不用模型文案冒充已登记的新任务。
- native 视频常在模块绑定 loadeddata 之前已解码，界面于是一直显示另一张图。现在绑定时立即检查 readyState，错误/恢复均同步。视频文件保持原始樱花动漫封面，备用图片直接提取同一视频原帧；右侧按钮下移。
- 旅行未抵达时 player.locationId 是记录用出发地，旧 UI/提示却当作身体仍在那里。现在显示出发地→目的地·途中，提示包保留 travel 和 turnStart，途中排除两端居民的对话、听见原话、普通人物操作和本地问话建议。继续赶路依据实际剩余分钟，仍由原抵达事件结算。
- 等待解析把“分钟”和“天”都截到365，等待555分钟只推进365分钟。现在按单位限制，总上限仍为一年；真实555分钟路程已测试抵达。

## 验证与诚实边界

153项 Node 回归通过。新增多 seed 开局/困惑、变更人物目标、降级记录、视频快载、20 seed 旅行在场、在途机械动作拒绝、长分钟等待与回合起始状态用例。独立只读审查发现未知目标被错译为势力事务、向死者问任务、在途攻击漏口；均先复现，再修复。原生窗口/DPI/launcher音乐锁、真实 MP3 解码与曲序、视频截图和补丁 Validate/Apply 另行验证。

前40个实际回合有38个由本地模型直接叙述、2个由引擎有限回应；44次模型请求平均约14.86秒，范围6.41–30.92秒。较晚复验记录见 playtests。不能用可提交率证明文学质量或完全事实正确。模型仍会把可能的线索说得过于确定、混淆尚未登记的物件/委托，也可能把数值或内在状态生硬说出来；事实校验并不能识别所有自然语言虚构。当前未实现在正常剧情中由任意文字自动建立任意因果链。开放提案仍由既有结构化操作协议限制，不能把未知效果说成已生效。

本机14B量化模型并未达到在线模型的全面质量和速度。既往 Ministral 8B测试较快但更易编造，见 LOCAL_AI_EVAL.md；没有悄悄替换当前 Qwen 或云端路线。后续应扩大真实跨场景测试与结构化事实协议，而非写死这些 seed 或重复堆提示词。
