# v4.1.0 因果成网 — 实际实现与扩展约定

这是 AI_WORLD_SIMULATION_VISION.md 的首个可运行因果层。所有下述状态进入 astraWorld.simulation 和 SQLite。不要按某个 seed 或例子写独立剧情分支。

## 回合与调用

已有机械动作仍由 Engine 结算；无法机械解析的言灵进入既有叙事请求。一次模型响应可以同时带 worldPlan.operations 和 blocks，没有额外的逐 NPC 请求。提案先在世界副本上执行，再校验结果叙事。被拒候选的修复从同一副本重新开始，不能重复加关系或给物品。普通对白仍是对白，不能直接变成杀人、移动、创造或属性改写。

astra-operations.js 提供创建人物/物品/势力/地点、保持 ID 的属性改写、所有权转移、成员/依恋/信任关联、社会认知、条件任务、事件规则及未结算概念。条件及效果属于受限数据表达式，不能执行模型生成的 JavaScript、SQL 或任意对象路径。新规则只在明确世界范围言灵中建立。身份改变保留家庭、历史、知识和物品引用。原有境界与数值边界继续由 astra-rules.js、astra-variables.js 统一结算。

开放式言灵登记因果债：创建24、属性改写8、关联6、规则30、委托12、转移/使用4；重复的同值改写和未结算概念不收代价，气血支出遵循原有至多40的方式，无敌状态仍转入债。已有机械言灵保持原代价。

## 因果与人物

astra-causality.js 将事实与观察者信念分开。直接受益/受损、事件时所属势力、依恋和已知受害史共同影响评价；没有固定“灭坏宗门所有人立即崇拜”分支。事件只结算一次，评价进入该人物关系值。亲眼见证可信度1；沿真实可通行道路延迟传播，每跳降低可信度，最多三跳。没有见证者的事不会凭空传播；道路毁坏阻断未抵达消息。

评价生成有来源的 NPC 计划。协助改变目标并登记相助意愿，导演可选择该机会；回避通过真实道路离开、排程抵达。死亡或目标失效使计划失效。原有 NPC 生计、家庭、修行、势力与时间算法仍运行。普通世界事件和人物行动产生的可测变化也进入因果记录，不得被记为玩家所为。

系统监听意图风险、境界变化、新委托、任务完成、终局和规则错误；提醒有稳定 ID 和来源，不必等玩家打开系统对话。不会替玩家行动。提醒进入行记、左侧系统区和伴行记忆，读档后仍可查看。

## 任务、效果、持久化

新委托有真实给予者、目标地点、可计算条件、截止时间和奖励。普通任务不能用创建时已满足的无关条件领钱；奖励来自给予者财富，已有委托占用额度。接取并真正达成条件后才结算一次。效果目前支持气血、财富、安全及受当前上限约束的境界提升，可带条件。转移更新双方行囊、唯一所有者及来源。

条件支持 all/any/not、eq/ne/lt/lte/gt/gte/exists 和安全字段引用。事件规则按版本与源事件去重，每次最多结算64项，其余进入持久待办。替换规则使旧版本待办失效。终局不继续发奖励。

WorldDatabase.cs 在 checkpoint 事务中增加 causal_events、world_beliefs、world_relations、world_rules、world_plans、companion_notifications、world_intents、world_commitments、causal_reports、rule_queue、world_transactions，以及按实体/事件索引的 causal_links、belief_index。完整副本保证恢复；投影与 checkpoint 同时提交，中途 SQL 失败一并回滚。手动读档使用既有分支机制，未来消息和计划不能带回旧分支。

## 保留的边界

这是可组合的通用因果基础，不是无限自由语义模拟已经全部完成。物品效果词汇、普通战斗和复写过去的历史重建仍有范围。无法表达的新概念保存为 unresolved 候选，系统明确说明未生效。不得把 description、对白或未注册属性说成机械效果。新地点需要道路才可普通到达。未承诺百小时完整终局或任意模型都与云端同质量。

云端仍遵守供应商限额。此次保留 provider/router、Groq 模型、密钥与请求门控；用本地传播和有界事实召回减轻请求量，不能声称无限调用。
