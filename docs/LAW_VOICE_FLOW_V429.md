# v4.2.9 言灵、人物与系统顺序

用户反馈近1000秒调息、复读和机械人物、改写忠诚不改态度、系统先剧透。目标是快速且真实的互动，不把隐藏等待当成消除真实额度。

根因与实现：

1. 429若Requested大于整个单次桶容量，旧队列会把retry-after写为凭据的全局nextAt，原请求需先等再报413，其他较小请求也受拖累。现立即报AI_INPUT_BUDGET，不污染后续队列；旧的已知超容量队首会在等待检查前终止并清掉它造成的旧nextAt。新enqueue会唤醒一次校验，仍遵守真正可重试429的原时刻。没有轮换供应商或Key绕配额。
2. 言灵用astra-reality-prompt将原始完整指令、真实指定目标（包括远处人物）、当前规则和所需字段送给同一模型，不携带无关长记忆、普通任务说明或长旁白要求。Engine完整世界和原子校验不缩减；413时仅一次更精简提示重试，不缩玩家命令或用concept.defer假称成功。已知言灵仍由本地直接结算。
3. 云端持久job保留不重发，前台默认12秒后返回AI_QUEUE_PENDING，保留原话/任务待续并释放UI；长429也不再让前台请求门睡近1000秒。不伪造答复或偷偷提交世界，真实配额仍可能暂时无法生成开放新回合。
4. 快对白修复recentTurns.dialogue不存在而漏掉真实blocks的错误，携带最近三轮的NPC/系统原话。personality支持明确言灵改写并记录因果，当前性格/关系优先旧态度；明确改写信任会清掉与新立场相反、由旧社交事件产生的avoid/support计划，其他义务不清除。
5. 共享对手戏规则：调皮不等于刻薄、谨慎不等于反复审讯。先答当前问题，未知不编，没新事件不重复拍门/威胁/催走。系统可接话、吐槽、安慰、提醒，但不强迫每轮出场；与NPC同一blocks顺序，可NPC→系统→NPC，无额外系统AI调用。
6. 正文播放器逐块完成时才更新系统侧栏，开场不从完整已保存系统记忆提前展示；存档仍保存完整回合，显示进度不改变世界结算。

复玩与复审追加：状态轮询最多间隔2.5秒，旧retryAt不能挡住已完成/已失败任务的读取；无动画历史重建仍同步按回合顺序，不能因空callback的await打乱存档对白。队列只在预测容量不足时，从前8项选择实际放得下的请求，真实provider nextAt与上游失败backoff仍严格保留；运行中的任务租约不重发，也不产生毫秒级alarm循环。

小探测能成功但正常剧情仍被预测挡住时，不可把所有新提示词一律按旧密度预留整桶：未测量的新提示词若被估计超过整个桶，允许一次真实校准，由真实429/413决定，不再仅靠预测等整桶。旧队列任务首次被原会话查询时会唤醒一次升级校验，避免只能等旧alarm触发才生效。

最终定位：v429-live-quota-diagnostic.json显示旧day-tokens预测limit200000/available704/refillRate0，冻结等待约5449秒；同一提示词直接Groq实际1761输入+300输出，1036毫秒成功。旧日额度既不逐步恢复，也未退回未用的最大输出预留。升级只移除无法证明仍有效的旧影子余额，真实429的meta.nextAt仍保留；新日预算支持恢复并按成功回复实际usage退补预留，retry-after是本请求可重试时刻，不再与整桶恢复reset混淆。诊断需原任务会话，只返回计数，不含Key、提示词或其他玩家记录。

开场已实际见面的人不能在第一句玩家回应时再被标为初见；metPlayer和opening-contact都属于已发生接触，不能丢掉后再让人物重新报身份。

真实续接已观察到普通新对白2872毫秒、复合性格/忠诚言灵1435毫秒。随后定位到仅仅在发言中写出NPC全名就会因numericFacts别名退出短通道；现保留在场者真实数值，只有远处/地点依赖走完整通道，去除未被引用的UUID出处并保留最近三轮对白，短视图上限4400字符。不能把一次试玩速度当作所有回合保证。

验收证据保存在Maintenance/Verification/v429-*。本地回归、线上实玩、界面和发布状态分别记录；最终汇总为v429-release-state.json。任意历史重算、全部故事账本字段言灵修改、任意新建筑发现仍不是已完成能力。不得将提示词改进等同于每句都达到真人品质，也不得承诺免费共享API任意高并发瞬发。
