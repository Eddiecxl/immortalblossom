# v4.2.1 自然互动与在场显示

用户要求通用于所有 seed：周围人物与世界一致；连续交谈不反复描写清晨景物，人物与系统像生活在世界里的人；内部数值仍影响机制，只在面板显示；音乐默认关闭；只有突破、任务完成/失败、主角死亡及终局弹窗。沿用已有回合、记忆、提案及事务链，不重做引擎或清除旧档。

根因：v4.js 读取 codex.characters（曾认识者）而非实际在场者。作者包精简 recentTurns 后只留下对白，缺少此前旁白开头；提示又鼓励每轮180–420字。言灵直接把操作类型与代价写进系统块。事件展示对普通掉血、物品、旅行、新任务均使用全屏弹层，且 Astra 任务终态未直接作为事件来源。

改动：nearbyCharacterRows 直接筛选当前地点活着且不旅行的 NPC；旅行中的主角不显示原地 NPC。保存短 narrativeOpening 与当前场景连续性信息，云端/本地共用写作指引，回复按内容定长，不强制铺景。保守的相似开头校验及内部评分校验触发现有修复流程，不提交虚假事实。不会证明理解所有自然语言；未命中保守校验的错误仍可能存在。

言灵仍100%执行已支持的明确指令，代价和关联照常落账；剧情仅表达实际结果和伤势。普通伤势不弹窗；任务终态直接比较世界前后。系统聊天遇内部评分可修复一次，仍无效则保留输入，不推进世界。人物态度、听闻、死亡/复活和去向沿用真实数据库，不能靠文字重置。

游戏默认 music=0，保留用户已明确保存的音量；静音不加载曲目，音效可继续，开启/下一首明确启用背景音乐。Launcher 原播放逻辑与歌曲保留。

验证进度：新增9项回归已观察RED→GREEN，涵盖三seed在场、生死/旅行、弹窗策略、任务终态、不复读、内部数值与自然价格、言灵真实落账、系统修复及静音曲目。真实 Groq 多轮试玩及发布状态继续记录在 Maintenance/Verification/v421-*；测试通过不等于所有叙事质量已完美。

真实试玩新增发现：一次候选返回普通小说文本，缺少JSON，导致耗费额外修复请求。Worker现在对system指令明确要求JSON blocks的回合使用response_format:json_object；普通连接探测保持文本模式，不锁定worldPlan的动态结构，仍由Engine验证。边界回归已观察失败后修复。官方依据：https://console.groq.com/docs/structured-outputs 。
