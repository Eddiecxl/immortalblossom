# 落仙：AI 世界模拟与主动系统——需求理解备忘录

状态：设计方向与现状审计，**不是已实现功能或补丁承诺**。本文件记录玩家所说的核心体验，后续引擎改动先对照这里及 `ENGINE_CONTRACT.md`，不能把下方示例写成专用剧情分支。

## 玩家真正要玩的是什么

这是一部会随玩家行动改写的长篇修仙小说，同时是有物品、人物、任务、规则、时间和因果的单人 RPG。世界种子给出开局条件和一条可见的路，但玩家可以跟随、绕开、破坏、创造另一条路。世界不能停在玩家输入的下一句：旁人有目标，会观察、误解、传播消息、行动；系统是有性格的伴行者，会在危险、机会、矛盾、意外和任务变化时**自己开口**，而不只是回答提问。言出法随可以改人物、身份、性别、物品乃至世界规则；改动之后所有有关联的规则都要从新状态结算，并长期留在 SQLite。玩家给出的例子只是验收样本，不是可枚举完的需求清单。

目标不是让 AI 单独编写一段「看起来合理」的后果，也不是让固定正邪标签决定所有人的反应。事件、事实、每个人知道什么、信什么、重视什么，以及他们能做什么，都必须是世界状态的一部分。AI 可以理解开放式意图、提出新实体/规则/后果候选，并写出有小说质感的表达；只有经过 Engine 检查、落账的变更才成为世界事实。对当前规则无法明确结算的新概念，应保留候选与语义、让系统解释不确定处，不能悄悄当成已生效，也不能伪装成玩家做不到。

## 目标回合链

玩家输入或世界定时事件 → 召回有关实体、历史、规则与未解决承诺 → AI 语义解析和结构化变化候选（行动、说话、指向、范围、直接效果、可能后果）→ Engine 在世界副本中检查能力、地点、时间、物品、规则与冲突并结算 → 因果传播器沿人物、组织、地点、契约、物品、知识的关联生成后续事件 → 各 NPC 按**自己实际观察或听闻**及价值观更新信念和计划 → 剧情导演从新世界状态选择可见机会与长期方向 → 系统触发器决定是否主动提醒/调侃/发任务 → AI 根据已结算的草稿事实写叙述与对白 → 校验后将世界、事件、关联、回合与系统消息在同一修订写入 SQLite，再更新 UI。持久化提交之前，全部变化都仍是可丢弃的草稿。

一项行动可能有立即结果、延迟结果、隐藏结果或零效果。每项后果都带来源事件、受影响实体 ID、可信度、可见范围和时刻。传闻与事实分开；同一消息可扩散、扭曲、被质疑。改写世界规则时，旧规则的依赖项必须失效重算；不能把旧叙事当成现行法则。跨回合重试要幂等，失败不能留下半个新人物或半件物品。

## AI 的职责与执行边界

可以把整个存档交给模型自由续写，但长程事实、数量和关联容易互相矛盾；也可以只用预设模板结算所有事情，但开放输入会不断碰到词表边界。建议采用 AI 理解与提案、Engine 通用执行、AI 再表达的组合：AI 参与意图、人物动机、社会评价、任务候选、新规则语义和剧情改道；Engine 管理引用、约束、执行顺序、实际效果与持久化。算法提供可组合的操作，而不为每条剧情写独立脚本。

“所有内容可改变”包括世界属性和规则；已有实体的稳定 ID 与来源记录继续保留，以维持同一人物的身份及所有关联。新人物、新物品和新规则可以建立新 ID；改变姓名、性别、形态或阵营不等于删除旧人物再生成一个替身。历史一般追加变化记录；明确改写过去时，需要标记被替代的事件并重建其后果，不能只删掉一段文字。

基础操作应覆盖创建/更新实体、建立/解除关系、增减/转移资源、状态转换、添加/消费效果、排程/撤销事件、建立/修订任务、更新观察者信念及改写规则。每个操作都带类型、目标 ID、来源事件、前置条件、范围和依赖；可组合成一次事务。新的机制优先用这些操作与声明式规则表达，无法表达的语义要明确记录为未结算候选，而不是只放进“装饰属性”中。

发言本身也有后果：威胁、承诺、欺骗、求助、示好或辱骂可以改变听者的信念、关系、计划和契约。但“我要杀你”是威胁，不等于已经执行杀人；玩家行动栏中的动作也先是意图。解析要保留假设、引用、否定、玩笑、目标歧义和能力差异，不能把随口提到的事全部强行实现。言出法随遵守玩家明确指令的范围，与普通发言分别结算。

系统触发可发生在意图被识别时、结果落定时、延迟后果抵达时；危险预警不应只等玩家受伤后才出现。触发依据与系统可知范围必须登记，系统能知道的风险不自动成为 NPC 的知识。预警强度取决于风险、紧迫度和证据，表达由人格决定；提醒不会替玩家选择。系统给出的任务须有真实来源、目标、完成条件、期限/取消条件及可兑现奖励，并与世界事件和承诺关联。

## 数据与调用成本

SQLite 需要同时保存当前实体/关系、不可混同的事实与观察者信念、规则及版本、因果事件边、延迟后果、NPC 计划、剧情承诺和系统触发记录。完整 checkpoint 保证恢复，事件账本解释变化来源，按实体 ID、关系类型、地点和事件时刻建立索引。文本摘要与 FTS 帮助召回叙事记忆，但不能代替所有权、数量、任务状态和因果引用。

全部记录带旅程/存档分支和修订号。读取手动档后，从该分支的事实与待办事件继续，不得让被放弃未来的记忆、复仇或系统提醒泄漏回旧时点。数据库、行记和 UI 使用同一已提交修订；角色改名或属性变化之后，旧引用按稳定 ID 解析为当前实体，同时保留历史时点的旧值。

每次请求只召回此次输入所牵连的局部关系图和关键长期事实；日常传播、边界、数量、时间、依赖失效和常见风险在本地计算。复杂或新颖的语义交给 AI，一次分析尽量批量覆盖同一事件的相关人物、后果与系统反应，不为每个 NPC 各发一次请求。已验证的通用规则可缓存复用；必须以输入事实与规则版本失效缓存，不能把上一轮剧情重复当答案。云端限额依然存在，额度不足时保留草稿并明确等待或使用有限本地结算，不能丢失动作或声称无限调用。

## 必需的通用模型

- **实体与关系图**：人物、势力、地点、物品、任务、身份、技能、规则都用稳定 ID。关系可有所有权、成员、亲属、恩怨、责任、见证、控制、依赖、目标等类型，并有生效/失效时间。属性允许扩展，但产生机械效果的属性必须有类型、边界和规则。
- **事件与认知**：世界发生了什么、谁看见、谁只听说、谁相信以及为什么相信必须分开记录。社会评价是人物/群体对事件的推断，不是主角身上的一个万能声望数字。若玩家消灭某势力，不同居民可能因受害史、利益、亲属关系和消息来源做出不同评价；消息传播后才形成更大范围的名声。这是通用社会认知结算，不能专为“坏宗门”写一条判断。
- **规则与因果传播**：常见变化通过可检查的前置条件、效果、依赖和排斥条件表达；言出法随可提出规则改写，但必须指明范围并校验新旧状态。引擎重复应用规则直至本轮稳定或达到有界预算，把未完成的远期影响排入事件队列。新规则可由 AI 候选生成受限、可验证的声明式表达式，不能直接执行模型生成的代码。
- **NPC 自主性**：人物的目标、价值、资源、风险认知和关系决定下一步。重要人物精细模拟，背景人群聚合模拟；只在必要时调用 AI 判断复杂开放情境，日常数值和传播用本地算法。人物不应因为玩家没输入就停住。
- **剧情导演**：种子给方向，不锁死路线。导演根据已发生事件和未解决承诺重新规划若干可达的下一步、阻力和终局条件；玩家偏离时重算而非把他拉回同一段情节。导演不能凭空重演已经完成的初见、入室或任务。
- **主动系统**：监听 Engine 事件与风险预测，触发危险预警、意外、突破、任务、人物关系、世界规则改变等消息。系统有语气与伴行记忆，可以幽默或欠嘴，但内容须引用有来源的事实；限频、去重并区分紧急提示与闲聊。主动消息不是新的世界事实，除非系统本身有已登记的能力和效果。

## 当前 v4 的位置与缺口

`astraWorld` 和 `WorldDatabase.cs` 已有完整世界快照、实体投影、历史、FTS 记忆与事务保存；`astra-scheduler.js` 会推动时间和既有事件，`astra-reality.js`、`astra-variables.js` 可结算有限的结构化变化。`astra-director.js` 主要从已发生的可见事件取线索，并在数回合平静后制造本地传闻。`astra-turn.js` 要求叙事 AI 不提出 Engine effects；`ai-turn.js` 的 Astra 系统频道在玩家主动提问时才运行。这些机制有价值，但尚不能让 AI 参与开放式世界后果规划，也没有通用的事件→观察者信念→社会传播→NPC 行动→系统主动提醒链。SQLite 完整快照可保存新增字段，但新关联与信念还没有专门索引和验收规则。

## 建设顺序与验收方式

先做事件/事实/认知/来源的统一账本和可回放事务，再做通用依赖传播器与受限规则表达式；随后接 NPC 信念及行动、动态剧情导演、主动系统触发器，最后让 AI 参与开放式候选生成和小说化表达。每层都用多个不同 seed 与新旧存档测试：同一因果规律适用于未预设的人物、势力与地点；信息未传播者不凭空得知；关系改变会影响任务、行动和对白；言灵改写后旧效果按新规则重算；AI 失败、重复请求与额度不足不破坏状态。验收不靠单个示例通关，而靠性质测试、生成场景、长回合模拟和真实模型试玩。

设计参考：[Generative Agents](https://arxiv.org/abs/2304.03442) 的观察、记忆、反思与计划；[Interactive Narrative: A Novel Application of AI for Computer Games](https://ojs.aaai.org/index.php/AAAI/article/download/8447/8306) 对涌现叙事、剧情管理和玩家自主性的区分。这里把两者结合成上述工程方案，是对研究和本项目需求的设计推断，并非这些论文已替本游戏解决全部问题。
