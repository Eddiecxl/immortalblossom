## 实际发现与修正

- 种子物品实例缺少 name，界面通过模板显示名称，AI/交付校验却找不到。补齐起始实例名称，并仅补旧档缺名，保留改名、稳定 ID、数量和所有权。
- 本地模型会相信玩家伪称的承诺，写“既然你收下了”，即使物品仍在 NPC 行囊。提示包明确当前所有权、最近转移及约定状态，blocks 状态声明由引擎检查；取得文字另作保守检查，拒收无实际交付的候选。
- 模型也会写 NPC“接过”却没有转移操作。普通动作的成功交付必须用 resource.transfer 结算；收取校验区分主角、NPC、疑问句、同名实例和同段里无关物品。不能凭旁白给物品。
- “开玩笑、想法、调情”之间出现重复旧句，本地提示减少旧对白范文，把新输入放在最后，保留原话和 SQLite 召回。大段重复的候选退回修正，不能靠改第一句掩盖复读。
- NPC 在世界时间推进后动身，原上下文丢掉其记忆，导致最后一句突然“不清楚”。departingNpcs 只保留本轮起初在场、随后动身者的最后回应事实；动身反馈去向，下一轮不冒充仍在场。其物品/任务权限没有被放宽。
- 本地模型口头答应归还，但没有记录承诺。针对本轮引用的真实持有物品，提示包含实际人物、物品和约定 IDs 的操作示例；人物仍可拒绝。具体交付承诺需要落账，询问去向和“给你解释”不算赠予。最后本地接受试玩已实际完成 pending→fulfilled，双方行囊及 SQLite 归属一致。
- 同基础名称物品的动作授权原先可能在转移/消费第一件后扩大至第二件。改为固定回合源集合，排除另一件完整名称中的子串；未授权的第二件会使整个提案拒绝回滚，机械已消费的物品也不能借名称授权另一件。
- Groq 实测返回 ITPM 429；原生代理将上游错误包装成字符串，原前端没读出实际23秒等等待时间。现在解析真实重试间隔，较长额度等待不早重试、不改本地路线，也不提交假的有限对话或世界推进。

## 验证范围与边界

201项 Node 回归通过，覆盖16 seed真实约定接受、拒绝、撤回、所有权变化、同意反问/否定、幂等交付、条件与跨任务依赖、奖励资金守恒、明确引用的较旧约定召回、原话记忆和在途/离场权限。新增跨12 seed任意物品的跨句取得断言校验、同名实例授权与整提案回滚。原生 SQLite SelfTest 的完整性检查为 ok，验证因果/承诺投影、检索、旧格式保护、过期 revision 拒绝、备份及中途失败回滚。

实际复玩同时包括正常问路/探索/赶路，以及荒诞自称、离题、调情、辱骂、道歉、记忆追问、物品给予、归还请求和伪称承诺。在安装后的本地 unusual 场次，7轮均提交，记忆回答引用真实发言；仍有生硬回复和未完全接住“自己的想法”的情况。正常无人在场的另一 seed 验证了实际行路与抵达，但不把无人场次说成人物交付成功。

最终 Groq 交付对照中，给予麻绳实际转移给顾青山；他拒绝归还后，玩家声称“你答应给我”被反驳，没有偷发回物品。5轮提交，SQLite 读回同一物品归属与 checkpoint。4轮经历429后按服务商间隔重试；物品归属追问有一次进入明确提示的有限回应。没有谎报这些NPC拒绝场次为“赠予约定已接受”。实际约定兑现及关联任务由多 seed 引擎回归验证。

最后本地接受场次5轮提交，实际归还约定兑现，玩家询问归属时答复与物品状态一致。最后一轮后果追问仍两次复读而进入有限回应；随后有限回应改为说明真实交付决定，而不是再次自我介绍。不能把这次降级说成模型已自然理解所有后果。

最终本地拒绝/后果场次5轮提交，NPC要求解释归还缘由，遭辱骂后表示不满，再次回答实际持有状态。此场没有已成立的赠予约定，不能将其写成 pending→declined 的实机证明；玩家不拿时物品仍由NPC持有，SQLite读回一致。最后后果追问仍降级，但实际展示的是“还在我这里，我还没有把它交给你”，没有再重置成角色介绍。正式约定拒绝、关联任务失效及无关任务保留由多seed自动回归验证。

可提交率不代表文学质量或所有事实完全正确。Qwen3 14B仍可能误解、重复或编造非机械细节；Groq也会生成多余细节或复读。自由输入在受支持的结构化操作内落账，尚不能表达任意新物理规律或证明任意自然语言一致性。保守文本校验不能替代语义理解。此次没有替换模型、重写seed、死亡/言灵范围、存档控制、原封面、开场影片或音乐。
